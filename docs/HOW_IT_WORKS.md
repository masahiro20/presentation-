# 平面図の読み込みとパース作成の仕組み（2026-11-18 時点）

社内向けの説明です。「PDF を入れると、なぜ 3D とパースが出てくるのか」「どこが図面から読んだ値で、どこが推定なのか」をまとめます。

## 全体の流れ

```
PDF の平面図
   │ ① 線・塗り・文字を取り出す
   ▼
ページごとの「線の集まり」
   │ ② 縮尺を決める → ③ 平面図のページと範囲を見つける
   ▼
階ごとの図
   │ ④ 壁 → ⑤ 窓・戸 → ⑥ 部屋 → ⑦ 階段・家具の記号
   ▼
階ごとの間取り
   │ ⑧ 上下階を重ねる → ⑨ 木造の格子（910）にそろえる → ⑩ 常識で補う・点検する
   ▼
建物モデル（部屋・壁・開口・階段・家具・敷地）   ← ここまでが「読み込み」
   │ ⑪ 高さ・屋根・外構を足して 3D にする
   ▼
3D（ブラウザの中でリアルタイムに表示）
   │ ⑫ 構図を自動で決める → ⑬ 下絵を描く → ⑭ 写真仕上げ（外部の AI）
   ▼
パース・資料・体験リンク・見積・日照
```

AI が絵から「推測」しているのではなく、**PDF の中の線を幾何学のルールで読んでいます**（⑭ の写真仕上げと、任意の「AI 設計士の確認」だけが生成 AI）。
だから同じ図面なら毎回同じ結果になり、読み違いは原因を特定してルールとして直せます。その代わり、ルールが想定していない描き方には弱いです。

## 読み込み（PDF → 建物モデル）

| 手順 | やっていること | 主なファイル |
|---|---|---|
| ① 取り出す | PDF の中の線分・曲線・塗りつぶし・文字を、座標つきで取り出す。スキャン（画像）の図面は、画像の太い線を壁として拾う別の経路に入る | `parser/pdfExtract.ts`・`rasterWalls.ts` |
| ② 縮尺 | 寸法線と寸法の数字の組から決める（縮小印刷でも合う）。無ければ「S=1/100」の表記、それも無ければ 1/100 | `parser/scale.ts` |
| ③ 平面図を見つける | 図面枠の図面名で、配置図・立面図・展開図・仕上表などのページを外す。残ったページで、壁がつながった塊を 1 つの図として切り出し、「1 階」「2 階」の見出しで階を決める | `parser/pageMap.ts`・`assemble.ts`（detectPlans） |
| ④ 壁 | **平行な 2 本の太い線の組**、または**壁の色の塗りの輪郭**を壁として読む。壁の厚みの分布から「この図面の壁厚」を決め、サッシの線などを壁から外す | `parser/walls.ts` |
| ⑤ 窓・戸 | 壁の途切れた所を開口と見て、中の細い線（サッシ）・扉の円弧・引戸の線・白抜きで種類を決める。すべり出し・FIX・室内窓・引込み戸も見分ける | `walls.ts`・`windowMarks.ts`・`passMarks.ts` |
| ⑥ 部屋 | 壁で囲まれた範囲を塗り分けて区画にし、室名の文字を当てる。帖数・面積の表記も読む。吹抜（× 印）・バルコニー・小上がり・土間を見分ける | `parser/raster.ts`・`labels.ts`・`assemble.ts`（buildFloor） |
| ⑦ 階段・記号 | 等間隔の平行線の繰り返しを階段として読む（直・かね折れ・折り返し・コの字）。細い線のまとまりを、大きさと形から家具・設備・車・植栽と判定する | `parser/stairs.ts`・`symbols.ts` |
| ⑧ 上下階を重ねる | 壁の重なりで位置を合わせ、階段の重なり・外壁・面積表の建築面積で検算する（半間ずれを直す） | `assemble.ts`（assembleModel） |
| ⑨ 格子にそろえる | 壁芯が 910（または 1000）の格子に乗っている図面は、壁・部屋・外形を格子へ寄せる。寸法が 3,640・2,730 のようにそろう | `parser/module.ts` |
| ⑩ 補う・点検 | 読めなかった玄関ドア・室内の戸・ガレージのシャッターを常識で補う。読み取りを 100 点満点で採点し「まず直す 3 つ」を出す | `ensureOpenings.ts`・`readingScore.ts` |

### 図面から読んでいるもの／推定しているもの

| 項目 | 平面図だけのとき | 補助データがあるとき |
|---|---|---|
| 壁・部屋・窓と戸の位置と幅 | 図面から読む | — |
| 床面積・建築面積 | 図面の面積表があればその値。無ければ読んだ形から | — |
| 階高・床の高さ | **標準値の推定** | 立面図の寸法、または 3DS から読む |
| 窓の腰高・高さ | **部屋と幅からの推定**（腰窓 900 など） | 立面図・3DS から読む |
| 屋根の形・勾配・軒の出 | **外観テイストの既定**（低勾配の片流れ・軒 100）と「上の階に接する側が高い下屋」の推定 | 立面図の屋根の線、または 3DS から読む |
| 天井高 | 既定 2,400（部屋ごとに手で変更） | 図面の「CH」表記は実施図にだけあり、まだ読んでいない |
| 仕上げ・色 | 外観・内観のテイストの既定 | 立面図の外部仕上表を読む |

**いちばん大きい弱点はここです。** 平面図には高さと屋根が書かれていないので、平面図だけだと外観は「それらしい推定」になります。

### 読み違いを見つける仕組み（自己点検）

- 読み取りの点数（帖数・面積表との突き合わせ、上下階の整合、戸と窓の有無）
- 木造の常識（壁の端は柱で止まる・直下率・梁のスパン）: `woodCheck.ts`
- 住まいの成立（玄関から行けない部屋・戸の向き先・階段の昇り口）: `livingCheck.ts`
- 建築の検証（階段の寸法・戸が壁に当たる・天井高。施行令 21・23・24 条）: `core/buildCheck.ts`
- 3D にした後の外観の点検（外壁の抜け・屋根の穴を光線で調べる）: `scene/selfCheck.ts`
- AI 設計士の確認（任意。図面の画像と読み取り結果を Gemini に見せて指摘をもらう。形は自動では変えない）: `app/aiDesigner.ts`

- **提案に使えるか**（2026-11-19〜）: 読み取りの点数とは別に、建築の重大警告・未確定の推定（高さ・屋根・窓の高さ）・担当者の確認状況を合わせて判断する: `core/readiness.ts`
- **誤認識の自動修正**（2026-11-19〜）: 階段の重大警告は原因（範囲・形・向き・階高の推定）を切り分け、根拠が十分なもの（A）だけ自動で直し、候補が複数（B）・情報不足（C）は画面で選んでもらう。直した内容は取り消せる: `core/stairDiagnosis.ts`・`core/autoFix.ts`
- **間取りと 3D の照合**（2026-11-19〜）: 3D に変える途中で形が変わっていないか（階の高さ・外壁の抜け・窓・戸・階段・屋根）を三角形で確かめる: `scene/geometryCheck.ts`

提出前には、お客様の図面 12 件を毎回読み直して外観まで立ち上げ、壁の抜け・屋根の穴・エラーが 0 であることを確かめています。
精度は `scripts/audit/accuracy.ts` で、調整に使った図面（12 件）と使っていない図面（15 件）を分けて、部門ごとに測ります（`docs/specs/accuracy-project/`）。

### 読める図面・苦手な図面

- **得意**: ARCHITREND の提案用の平面図（1/100、壁が塗りか太線、室名と面積表つき）
- **読めるが粗い**: スキャンした図面・手描き風の図面（画像から壁を拾うので細部が落ちる）
- **下書きまで**: ご契約後の実施図（平面詳細図 1/50。壁が下地・柱・仕上げの多重の線）。2026-11-18 に読めるようになったばかり
- **読まない**: 立面図・展開図・配置図は平面図としては読まない（立面図は高さ・屋根・窓の高さの補助に使う）

## パース作成（建物モデル → 絵）

| 手順 | やっていること | 主なファイル |
|---|---|---|
| ⑪ 3D にする | 壁を階高まで立ち上げ、開口を抜いてサッシ・戸を入れる。床・天井・基礎・巾木・階段を作る。屋根は外形を長方形に分けて自動で掛ける（切妻・寄棟・片流れ・陸屋根、下屋、鼻隠し・軒樋・軒天）。外構（駐車場・アプローチ・植栽）と想定の街並みも自動で置く | `scene/building.ts`・`roof.ts`・`landscape.ts`・`town.ts` |
| 家具 | 図面の記号を読めた所はその位置に、読めない部屋は種類と窓・戸の位置から壁際の空いた所に置く | `scene/furniture.ts` |
| 素材・光 | 外観・内観のテイスト（御社の実例に寄せた既定）で素材を決める。太陽は日照の設定（方位・日時）と同じ。空は実写の空（HDRI）。室内は窓からの光とダウンライト | `scene/materials.ts`・`hdri.ts`・`interiorLights.ts`・`styles/presets.ts` |
| ⑫ 構図 | 外観は道路側の 2 点透視（縦線をまっすぐに）・庭側・鳥瞰・夜景。内観は部屋ごとに、奥行き・窓の見え方・家具との重なりを点数にして、いちばん良い立ち位置を選ぶ | `scene/shots.ts` |
| ⑬ 下絵 | ブラウザの中のリアルタイム描画（影・環境遮蔽つき）。止まると高い解像度で描き直す。書き出すときは 2 倍の解像度で描いて縮小し、写真風のトーンに整える | `scene/viewer.ts`・`studio.ts`・`photoFinish.ts` |
| ⑭ 写真仕上げ | **写真品質と動画はツールの外で仕上げる方針**。下絵と一緒に「形を固定するための画像」（奥行き・面の向き・線画・素材の塗り分け）を書き出し、外部の画像 AI・動画 AI に渡す。ツールの中から Gemini の画像生成を呼ぶ経路もあり、仕上がりの形が下絵とずれていないかを照合する。Blender（Cycles）に渡す依頼ファイルも作れる（ボタン化は未） | `scene/passes.ts`・`app/aiFinish.ts`・`scene/renderJob.ts` |

### パースの質を決めているもの

1. **形の正しさ**（屋根・窓の高さ・階高）… 平面図だけでは推定。ここが違うと、どれだけ質感を上げても「うちの家ではない」絵になる
2. **構図と光**… 自動。御社のご提案の静止画（Twinmotion）と見比べて寄せてきた
3. **質感**… ブラウザのリアルタイム描画の限界がある。写真品質は ⑭ の外部仕上げで取る方針

## もっと良くするために効くもの（効果の大きい順）

1. **正解のセット**: 同じ日付の「平面図・立面図・3DS・ご提案の静止画」を 10〜20 邸ぶん。今は読み取りの良し悪しを主に「つじつま」で測っているが、3DS があれば壁・窓・屋根のずれを数字で採点でき、まとめて直せる
2. **書き出しの型をそろえる**: 平面図の PDF に、立面図 4 面・屋根伏図・面積表を必ず入れる（同じ PDF でも別ファイルでもよい）。高さと屋根が「推定」から「図面どおり」に変わる
3. **設計士の手直しの記録**: 読み込んだ後に手で直した結果を残す（「評価用に保存」）。自動の読み取りとの差が、次に直すべき所の一覧になる
4. **合格の線を数字で決める**: 例「床面積 ±1%・窓の数が一致・屋根の形が一致・読み込み後の手直し 5 分以内」
5. **ゴールの絵を決める**: 構図の種類ごと（外観正面・LDK・キッチン・寝室）に、御社がいちばん良いと思う 1 枚（できれば竣工写真）
