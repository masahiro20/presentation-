# 建築として成り立つかの検証（buildCheck）

2026-11-17。検証用ブランチ `claude/3d-quality-lab` のみ（本番には出していない）。

## ねらい
図面の線をそのまま 3D にすると、戸が壁にめり込む・階段が上の階につながらない・窓が天井の上にある、といった
「建物として不自然な 3D」ができることがある。読み取った間取りを数値で確かめ、根拠と確からしさを付けて示す。
**形は直さない**（直すのは「形が変わらないことが確定できるもの」だけ。下の「補正」）。

- 使う人: 設計士・営業（読み込み直後に、直すべき所が分かる）
- 見る人: お客様には出さない（社内の確認用）。目線は使う人だけでよい

## 既存の検証との分担
| 検証 | 見るもの |
|---|---|
| 木造の常識（`parser/woodCheck`） | 柱・梁のスパン・直下率・壁の端 |
| 住まいの成立（`parser/livingCheck`） | 玄関から行けない部屋・戸の向き先・階段の昇り口・採光 |
| **この検証（`core/buildCheck`）** | 建具と壁の位置・戸の可動範囲・階段の寸法と上下階の接続と頭上・階の高さ・壁の重なり |

## 問題の持ち方（`BuildIssue`）
種類 `kind`／深刻さ `severity`（重大 critical・要確認 confirm・参考 note）／階 `level`／対象 `target`／場所 `at`／
根拠 `reason`（測った値つき）／参照した基準 `basis {type, ref}`／確からしさ `confidence`／すすめる対応 `advice`／測った値 `values`／補正 `fix`。

### 基準の種類（混同しない）
| type | 意味 | 例 |
|---|---|---|
| `law` | 法令の必須条件。条文を e-Gov で確認したものだけ | 階段の蹴上・踏面・幅、居室の天井高 |
| `geometry` | 形・座標の破綻（物として成り立たない） | 壁からはみ出した建具、床の高さの食い違い |
| `structure` | 構造上の成立条件 | **この検証では判定しない**（安全性を推測で保証しない） |
| `practice` | 一般的な住宅設計の寸法・慣習（違反ではない） | 室内戸の幅、階段の頭上 |
| `ergonomics` | 使いやすさ（違反ではない） | 急な階段 |

### 使っている法令の数値（2026-11-17 に e-Gov の現行条文で確認）
| 条文 | 数値 | 使い方 |
|---|---|---|
| 建築基準法施行令 第 23 条 1 項ただし書 | 住宅の階段: 蹴上 23cm 以下・踏面 15cm 以上 | 外れたら重大 |
| 同 表（四） | 幅 75cm 以上 | 読み取った範囲の寸法なので要確認（60cm 未満は重大） |
| 同 表（四） | 蹴上 22cm 以下・踏面 21cm 以上 | 住宅では必須ではないので「参考」（昇りやすさの目安） |
| 同 第 21 条 | 居室の天井高 2.1m 以上（平均） | 階の天井高が下回れば要確認（平均で判定する規定なので重大にしない） |
| 同 第 24 条 | 高さ 4m 超の階段は 4m 以内ごとに踊場 | 直階段で階高 4m 超なら要確認 |

法令の数値ではないもの（`practice`・`ergonomics`）: 戸の幅 600mm・450mm、階段の頭上、階高 2.3〜3.6m。画面にも「法令の数値ではない」と出す。

## ルール（実装済み）
| 優先 | 種類 | 判定 | 深刻さ |
|---|---|---|---|
| ④ | `opening-no-wall` | 建具の壁が無い | 重大 |
| ④ | `opening-outside-wall` | 壁の端から 15mm 超はみ出す | 重大 |
| ④ | `opening-below-floor`／`opening-above-story` | 下端が床より下／上端が階高を越える | 重大 |
| ④ | `door-above-ceiling` | 戸の上端が天井より 60mm 超高い | 要確認 |
| ④ | `openings-overlap` | 同じ壁・同じ高さで 60mm 超重なる（上下に分かれた窓は除く） | 重大 |
| ② | `door-narrow` | 人が通る建具の幅 450mm 未満／600mm 未満（読めずに置いた出入口は要確認どまり） | 重大／要確認 |
| ① | `door-hits-wall` | 開き戸を 15° ずつ 90° まで開き、板が別の壁の体に入る角度を出す。反対へ開けば当たらないかも調べる | 45° 以下は重大、それ以外は要確認 |
| ③ | `stair-riser`／`stair-tread`／`stair-width` | 階高 ÷ 段数、範囲 ÷ 段数、1 列の幅 | 上の表 |
| ③ | `stair-riser-steep`／`stair-tread-short` | 住宅の特例の中だが一般の階段より急・浅い（蹴上は段数が図面から読めたときだけ） | 参考 |
| ③ | `stair-no-upper-floor`／`stair-not-connected`／`stair-range-mismatch` | 上の階が無い／上の階に重なる階段が無い（重なり 15% 未満）／降りる階段と範囲が合わない（75% 未満） | 重大／要確認 |
| ③ | `stair-headroom` | 階段の真上の 5 割超に、上の階の部屋の床（吹抜・階段以外）がある | 要確認（8 割超は重大） |
| ⑤ | `floor-stack`／`stair-floor-gap` | 床 ＋ 階高 ≠ 上の階の床（20mm 超） | 重大 |
| ⑤ | `ceiling-over-story`／`ceiling-low`／`story-height-unusual` | 天井が階高に納まらない／2.1m 未満／階高が珍しい | 重大／要確認／参考 |
| — | `walls-overlap` | 同じ線の上で 2 枚の壁が 300mm 以上重なる | 要確認 |

## 補正（形を変えないものだけ）
`applyBuildFixes`: **もう 1 枚の壁にすっぽり入り、建具も高さの指定も無い二重の壁**を消す。消しても壁の体は同じなので形は変わらない。
画面ではボタン（「重なった壁を消す」）を押したときだけ実行する。読み込み時に自動では掛けていない（試作段階）。
それ以外（建具の位置・幅、階段の範囲・段数、階高、戸の開く側）は、原因が 1 つに決まらないので直さない。

### 見直しで消した誤検出
- 戸が「90° で壁に当たる」9 件: すべて、横の壁に沿って開き切るふつうの納まり／戸の端が角の壁に数十 mm 掛かる読み取りの誤差だった。
  壁の体を長方形で判定し、90° で板と平行に並ぶ壁は当たりにしないようにして 0 件に。
- 「上の階に降りる階段が無い」4 件: 3 階建ての中間の階は「昇る階段」1 つで持つデータの決まりだった。向きを問わず重なりで判定。
- 「急な階段（蹴上 223mm）」8 件中 7 件: 階高 2,900（標準値）÷ 13 段（推定）で、どちらも推定。段数が図面から読めたときだけ出す。

### 正解データが無く、測れていないこと
- 見落とし（実際は問題なのに出なかった数）。12 邸に「建築としての問題の正解一覧」が無い。
- 戸が壁に当たる検出は、実データで 1 件も出ていない（合成データのテストでだけ確認）。

## まだのこと
- ① 戸と**家具**の干渉（家具の配置は 3D 側で決まるので、同じ配置を検証へ渡す口が要る）
- ② 通路の幅（ホール・廊下の有効幅）。到達できるかは既存の「住まいの成立」が見ている
- 3D 上のハイライト／読み込み時の自動補正／AI 設計士の確認へ、この検証結果を渡す
- 立面図の階高が読めた邸での階段の再検証（いまは 12 邸とも階高が標準値）
