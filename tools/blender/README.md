# 高品質パース（Blender / Cycles）の試作

プレゼンツールの家を、Blender の Cycles で写真品質に描くための試作です。**本番のアプリには組み込んでいません。**

## 流れ
1. ツール側（`src/scene/renderJob.ts`）が「レンダリングの依頼」を作る
   - `house.glb` … 形（建物・屋根・家具・外構。単位 m・Y 上。メッシュごとに材料キー `matKey`）
   - `job.json` … カメラ（位置・注視点・縦の画角・2 点透視のシフト）、太陽の向き・時間帯、材料キーごとの素材の種類、
     **形の検算値**（全体と材料キーごとの外形・三角形の数）、推定値の一覧
2. `render_job.py` が Blender で読み込み → **形を検算** → カメラ・空と太陽・素材 → Cycles で描く → 画像と `*.report.json`

```
blender --background --python tools/blender/render_job.py -- --glb house.glb --job job.json --out out.png --width 1920 --samples 256
python tools/blender/render_job.py --glb house.glb --job job.json --out out.png        # pip の bpy（Blender 5.2 LTS）でも同じ
python tools/blender/render_job.py ... --check-only                                     # 形の検算だけ
```

## 決まり
- **形は編集しない**。触るのは素材・光・カメラ・描画の設定だけ。
- 読み込んだ形が依頼の検算値と **1mm を超えて**違えば、描かずに終了コード 2 で止まる（座標系・単位・縮尺の取り違え、書き出しの欠けを見つける）。
- 乱数の種は固定。ネットワークは使わない。同じ依頼なら同じ絵。

## 試作で分かったこと（吉田様邸）
- 検算: 65 部位・最大のずれ 0.005mm で合格。最初の版では「検算値に想定の街並みを含め、GLB には含めない」という食い違いを検算が見つけた。
- 2 点透視のシフト: Blender は、センサーを縦で合わせているとき「画面の高さ = 1」。three.js の値（高さの半分 = 1）の 0.5 倍。
- 重なった面: three.js の形には、同じ平面に面が二重に重なる所がある（つながった 2 枚の壁の重なり）。Cycles ではそこが真っ黒になる。
  形は変えず、素材側で「2mm 以内で当たった光の線は素通し」にして回避した（`harden_material`）。元の形の重なりを無くすのが本筋（今後）。
- 片面の素材は、three.js と同じく、カメラから見た裏面を描かない。
- 速さ: CPU 4 コア（GPU なし）で、1280×720・64 サンプル・ノイズ除去ありの外観が約 1 分。

## まだ無いもの
- 想定の街並み・周辺の建物（GLB に入れていない）。雲のある空（いまは物理の空）。
- 夕景・夜景の室内の灯り（照明の位置を依頼に入れていない）。
- 素材の作り込み（いまは GLB の素材をそのまま使い、ガラス・床の艶だけ調整）。御社の素材の型はこれから。
