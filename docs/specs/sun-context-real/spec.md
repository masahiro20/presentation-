# 日照の周辺環境を実物に近づける（Google の API キーなしで）

2026-11-17。方針: Google の API キーは発行しない。キーの要らない公開データで質を上げる。

## いまツールにあるもの（コードで確認）
- 周辺建物の形: PLATEAU（実測の高さ・屋根の形）。無い地域は国土地理院の建物＋推定の屋根。色付きで表示。
- 地面: 国土地理院の航空写真の板（220m）と標高。道路・緑地・街路樹（OpenStreetMap）。
- **PLATEAU の写真つき 3D（LOD2 テクスチャ付き）を敷く経路はすでにある**（`sunStep.ts` の `setEarth('plateau')`・`googleEarth.ts` の `urls`）が、
  画面の選択肢からは外してある。外した理由（PROGRESS 2282 行）: 住宅地は LOD1 の白い箱で写真が無い／名古屋市 2022 年度版は粗いタイルから細かくならなかった。

## 調べて分かったこと（2026-11-17）
| 手段 | キー | 見込み | 根拠・注意 |
|---|---|---|---|
| A. PLATEAU の写真つき建物 | 不要 | 中心市街地では大、**住宅地では小** | 索引 448 市区のうち 301 市区に LOD2 写真つきがあるが、写真つきなのは主に中心部の建物。名古屋市中区（栄）は全体 57MB・65 タイル・WebP の写真入りで、キーなしで取れることを確認。以前の「細かくならない」は再調査が要る（未解決） |
| B. 空中写真から屋根の色を拾う | 不要 | **住宅地で効く**（御社の案件の大半） | 建物の足元の範囲で航空写真の色を平均して屋根に塗る。どの地域でも使える。未実装 |

キーなしで Google 実写 3D と同じ水準（写真測量の街並み）を全国で出せる公開データは、調べた範囲では見つかっていない。
PLATEAU の写真は航空写真の切り出しで、近くから見ると粗い（国交省の技術資料）。鳥の目線〜斜め上からが向く。

## 進め方（案）
1. B（屋根の色）＋ D（写真の範囲）: 住宅地の見え方を底上げする。影の計算には触れない。
2. A の再調査: 栄で「細かくならない」原因を調べ、直れば「写真つき（PLATEAU）」を選択肢に戻す。写真つきがある地域では自動で勧める。
3. C（窓の並び）。

## 表示の決まり
地理院タイルは、サーバーから都度読み込んで表示するなら出典の明示だけで使える（いまも画面に出典あり）。空中写真の種類ごとの条件は実装のときに地理院の一覧で再確認する。

## 2026-11-18 実装: 屋根の色を航空写真から拾う
- 画面で確かめて分かったこと（住宅地・PLATEAU 未整備の地点）: 屋根に航空写真をそのまま貼る・外壁に窓の並びを描く・航空写真 330m は**すでに入っていた**（上の表の「未実装」は誤り。C・D は実装済みだった）。
  弱かったのは、斜めから近くで見たとき、屋根に貼った写真（1 画素 約 0.5m）が大きくぼけ、写真のずれで隣の道路・庭の色が屋根に乗ること。外壁もどの家も白かった。
- 直したこと: 建物の足元の内側（縁 3 割を除く）の写真の色の中央値を、その建物の屋根の色にする（`src/sun/roofColor.ts`）。写真の影・白飛びは屋根らしい明るさへ寄せる。
  写真の外・画素を読めないときは、これまでの決まった色のばらつき。体験リンクにも同じ色を渡す（`ShareNeighbor.roof`）。外壁の色に少し濃いベージュ・グレーを足した。
- 影・日照の計算には関わらない（見た目だけ）。
- 残り: 近くで見たときの地面の写真の粗さ（地理院の写真の解像度の限界）。PLATEAU の写真つき（中心市街地）の再調査。
