# 仕様書・チケットの置き場所（スキル用）

`/to-spec`・`/to-tickets` などのスキルが「issue tracker に publish する」「チケットを取ってくる」と言うときの、このリポジトリでのやり方。

GitHub の Issue は使わず、リポジトリの中の Markdown に置く（Issue を作るのは外に出る操作になるため。使うと決めたときは、このファイルを書き換える）。

## 置き場所

- 機能ごとに 1 フォルダ: `docs/specs/<機能の短い名前>/`（半角英数をハイフンでつなぐ。例: `kitchen-lighting`）
- 仕様書: `docs/specs/<機能>/spec.md`
- チケット: `docs/specs/<機能>/issues/<NN>-<名前>.md`（`01` から。1 チケット 1 ファイル。まとめて 1 ファイルにしない）
- 状態は、各チケットの先頭近くの `Status:` 行に書く
  - `ready-for-agent`: すぐ着手できる
  - `ready-for-human`: 人の判断・作業が要る
  - `done`: 済み
- 先に終わらせるチケットは `Blocked by:` 行に番号で書く
- やり取りの記録は、ファイルの末尾の `## Comments` に足していく

## 「publish する」と言われたら

上の場所にファイルを作り、コミットしてプッシュする（`CLAUDE.md` の約束どおり）。

## 「チケットを取ってくる」と言われたら

そのパスのファイルを読む。番号だけ渡されたら、`docs/specs/` の下から探す。

## 守ること

- 文面は日本語で書く。
- お客様のフルネーム・住所・連絡先・図面は書かない、置かない（姓＋様まで）。
- 全体の進み具合・方針転換・やめた機能は、今までどおり `PROGRESS.md` に残す（仕様書とチケットは個別の機能の詳細、`PROGRESS.md` は全体）。
