# 仕事の進め方（すべてのプロジェクト共通）

このファイルは、どのプロジェクト・どのセッションでも最初に読む「基本の約束」です。
プロジェクトごとの約束は、各リポジトリの `CLAUDE.md` に書きます。

## 1. いちばん大事にすること: 「誰目線で作るか」

ツールやサービスを作るとき、機能より先に「誰が使い、誰が見て、誰が判断するのか」を決める。

- **作る前に、目線を書き出す。** 例（住宅のプレゼンテーションツール）:
  - 使う人: 設計士・コーディネーター・営業 → 速い・迷わない・手戻りがない（業務効率）
  - 見る人: お客様 → ワクワクする・分かりやすい・安心して決められる（体験）
  - 決める人: お客様のご家族、上司・社内の承認者 → 根拠・金額・比較が一目で分かる
- **最終的に誰の目に触れるかを軸にする。** 業務効率化のツールでも、出てくるもの（資料・画面・リンク）をお客様が見るなら、
  「作り手が楽になったか」だけでなく「受け取った人が見てワクワクするか・分かるか」で良し悪しを判断する。
- **目線は 1 つで足りるときと、複数で見るべきときがある。** どちらなのかを毎回はっきりさせる。
  - 社内だけで使う作業ツール → 使う人の目線だけでよい（見た目より速さ・確実さ）
  - お客様に出るもの（提案資料・共有リンク・見積書・図面） → 使う人の目線＋お客様の目線の両方で確かめる
  - 迷ったら両方で見る。片方だけで良いと判断したなら、その理由をひとこと残す
- **出来上がったら、その目線の人になりきって見直す。**
  「この画面をお客様が初めて見たら何が分かるか」「設計士が忙しい日に使ったら何回クリックするか」を、実際の画面（スクリーンショット）で確かめてから出す。
- 専門用語は、見る人に合わせる。お客様向けは専門用語を使わず、社内向けは正確な用語で。

## 2. 進め方

- 日本語でやり取りする。
- 許可を待たずにどんどん進めてよい（取り返しのつかない操作・外部への公開・お金がかかる操作だけは確認する）。
- できたと言う前に、自分で動かして確かめる。不具合が他にも起きていないか、似た所・他のデータでも確かめてから出す（PDCA を自分で回す）。
- 作ったもの（画像・資料・画面）は、見える形で渡す。
- 大きな方針転換や、やめた機能・あとでやるアイデアは、プロジェクトの進捗メモ（PROGRESS.md など）に残す。

## 3. お客様の情報

- お客様の図面・個人情報は、作業用の場所にだけ置き、リポジトリや公開の場所に入れない。
- お客様のファイルを勝手に公開・共有しない。
