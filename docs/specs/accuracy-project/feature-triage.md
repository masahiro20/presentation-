# 機能の整理（2026-11-19）

精度向上を最優先にするため、130 以上の機能を「中核として維持・改善／高度な編集に残す／開発を止める／統合する／廃止を検討」に分けた。
**どの機能も削除していない。** 保存済みのプロジェクト（JSON）もそのまま開ける。
利用頻度の記録が無いので、分類は「提案資料を作る流れに必要か」「完成度」「精度向上との関係」で判断した（実際の利用頻度は、今後の操作の記録で確かめる）。

| 区分 | 意味 | 今回の扱い |
|---|---|---|
| A 中核 | PDF → 3D → 図面・見積・資料の流れに必須 | 精度の改善を集中する |
| B 高度な編集 | 設計担当者が手直しに使う | 残す。営業向けの基本画面からは一段奥へ（今後） |
| C 一時停止 | 精度向上に直接関係しない | 新しい開発を止める（動いている分はそのまま） |
| D 統合 | 似た機能が分かれている | まとめる候補 |
| E 廃止の検討 | 使われていない／方針と合わない | 利用状況を確かめてから判断（今回は消さない） |

## 2026-11-19 画面から外したもの（ご了承済み「必要のなさそうな機能は今は外していい」）
`src/app/features.ts` の切り替えで画面から外しただけで、**コード・保存データ・テストは残している**（true に戻せばすぐ戻る）。

| 機能 | 外した理由 |
|---|---|
| パースの「写真の仕上げをツールの中で」（Gemini の画像 API） | 決まり「写真仕上げはツールでは作らない（外部で仕上げて取り込む）」と逆。有料 API・図面の外部送信。外部で仕上げる流れ（書き出し → 取り込み）は残す |
| 読み込み結果の「AI 設計士の確認」（Gemini） | 有料 API・図面の外部送信。精度は建築のルールと正解データで上げる方針 |
| 日照の「点群で実測する」 | 点群のファイルを用意する案件が無い |
| コーデのステップ（2026-11-17 に外し済み） | 別ツールの領分 |
| ヘッダーの「お客様に渡す」（体験リンク）（2026-11-20） | ご指示。提案資料（PDF・HTML）の書き出しは「資料」に残す |
| 打合せ・社内の書類（2026-11-20）: 打合せメモ（議事録の下書き）・設計レビュー・前回からの変更・契約前チェック・月々の支払い試算 | ご指示。入力済みの内容は保存データに残す |

日照の「Google 実写 3D」は 2026-11-19 にいったん外したが、2026-11-20 のご指示で戻した。

外していないもの: 歩く体験・ルームツアーと街並みの下絵の動画（外部の動画 AI に渡す下絵なので決まりと合う）。

## A 中核（維持・改善）
- PDF の読み取り（壁・窓・戸・階段・部屋・寸法・縮尺・方位・面積表）、立面図・3DS からの高さ・屋根
- 読み込み結果の確認（読み取りの点数・建築の検証・**提案に使えるか**・**自動で直した所**・**修正案**）← 今回の中心
- 方眼での修正（壁・窓・戸・部屋名・階段・柱）
- 3D の生成（建物・屋根・階段・建具・家具の自動配置）と外観・内観のパース（構図の自動選択）
- 図面（平面図・立面図）、概算見積（積算との突き合わせ済みの決め方）
- 提案資料（PDF・HTML）、体験リンク

## B 高度な編集（残す・設計担当者向け）
- 3D の直接操作（選択・ハンドル・寸法入力・矢印キー）、屋根の修正ツール（辺・棟・向き・軒の出）、屋根を点で描く道具
- 窓・戸の幅の伸縮・割付チェック、壁の高さ（袖壁・パラペット・腰壁）、天井高の範囲指定、床の段差
- 階段の編集（種類・曲がる向き・回り段・ひな壇・桁・踏板）、吹抜の手すり
- ガレージのシャッター、庇、外構の物、敷地の高低差、敷地の修正
- 上下階の重ね合わせの道具、プラン 2 つの比較、平面図シートの配置

## C 一時停止（新しい開発を止める）
- 日照まわりの拡張（周辺建物の精度、PLATEAU、Google 実写 3D、日照の感覚的な操作、日影の 4 季節動画）
- パースの写真仕上げ（Gemini）・Blender 連携のボタン化・動画（ルームツアー・街並みの下絵・シネマ）
- 歩く体験の拡張（目線・アクション・広角・右下の平面図）
- 体験リンクの拡張（要望の書き込み・いいね・総額が動く）、暮らしの動線・収納の量・視線チェックのページ
- 議事録の下書き・プランの差分・設計レビューのページ・契約前チェック・支払い試算
- AI 設計士の確認（Gemini。有料 API・図面の外部送信を伴うので、今回の方針では使わない）

## D 統合の候補
- 「木造の常識チェック」「住まいの成立チェック」「建築の検証」「読み取りの点数」→ 読み込み結果の「提案に使えるか」に一本化（今回、4 つの欄に整理した）
- 「読み取り精度の評価用に保存」と「修正履歴」→ 正解データの保存に一本化（今回、確認済みか・操作の回数と時間を添えるようにした）
- 3D の「窓・戸」の道具と方眼の窓・戸の編集 → 同じ部品で（今後）

## E 廃止の検討（利用状況を確かめてから）
- コーディネートのステップ（すでに画面から外してある。別ツールの領分）
- 体験リンクの「仕様を選ぶ」・資料の仕様決定書（コーディネートと重なる）
- PLATEAU 写真つき LOD2 の経路（画面の選択肢から外してある）
