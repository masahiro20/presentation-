# ARCHITREND ZERO との連携と、読み取り精度を上げる道筋

## いま使えるもの（実装済み）

| ARCHITREND から出すもの | このツールで読めること | 精度 |
|---|---|---|
| PDF（プラン図・平面図） | 壁・部屋・室名・帖数・開口・階段・家具記号・方位・接道 | 平面は高い。高さは標準値の推定 |
| PDF の **立面図ページ**（同じ PDF に入れる） | 1 階床（GL+633 など）・各階の階高・最高高さ・最高軒高・屋根勾配 | 書いてあるとおり（文字を読む） |
| DXF（図面印刷の DXF） | PDF と同じ（線と文字が正確） | PDF と同等〜少し上 |
| **3DS**（3D の書き出し） | 位置を合わせて、各階の床の高さ・窓の腰高と高さ・図面で読めなかった窓・屋根の形と勾配・最高高さ | 3D のとおり（mm） |

- 3DS の使い方: 日照 →「設計の 3D データ（3DS）で正確な建物にする」で 3DS を読み込む → 自動で間取りに合う →
  「3D データの高さ（床・窓・屋根）を間取りに反映」。パース・図面・見積の元になる間取りが直る。
- 有元様 F プラン（PDF）と同じ日の 3DS で確認: 床 GL+640 / 3,220 / 6,120（立面図の 633 / 階高 2,580 と一致）、
  窓 3 か所の高さを合わせ、図面で読めなかった窓 5 か所を追加。

## 次の候補（精度の伸びが大きい順）

1. **IFC 読み込み（ZERO Ver.12 は IFC 出力が標準）**: 壁・窓・ドアが「部材」として、部屋名・床・屋根・高さと一緒に出てくる。
   推定がほぼ無くなる（平面の読み違い・窓の取りこぼしが原理的に起きない）。実物の IFC が 1 件あれば作れる。
2. **3DS を読み込みの段階で一緒に入れる**: いまは日照の画面から。図面読込で PDF と 3DS を一緒に落とせば、最初から高さが正しい状態で立ち上がる。
3. **立面図から窓の高さ**: 立面図の窓の線の上下端と FL の線の位置から、窓ごとの腰高・高さ（3DS が無いとき）。
4. **建具表・仕上表のページ**: 建具記号（AW-1 など）と W×H・品番が表で出せるなら、窓の大きさ・種類と仕上げのコーディネートの初期値に使える。
5. **断面図**: 天井高・吹抜・勾配天井。

## ARCHITREND ZERO にどこまで入り込めるか

- **公開の API（プログラムから直接操作する口）は見当たらない**（福井コンピュータアーキテクトの公開情報の範囲）。
  クラウド連携（ATDrive・3D カタログ.com）は別契約のサービス。
- **ファイル経由はすぐできる**: ZERO から PDF・DXF・3DS（・Ver.12 なら IFC）を書き出して Google ドライブに置けば、こちらで読める。
- **画面操作（Computer Use）**: ARCHITREND が入っている Windows パソコンで Claude のデスクトップアプリを使えば、
  Claude がその画面を見てクリック・入力できる（決まった書き出し作業の代行など）。図面を描かせる用途は、操作が多く遅いので現実的ではない。
- **逆向き（このツール → ZERO）**: このツールの間取りを DXF で書き出して ZERO に下図として読み込むことはできる（壁・開口の線）。
